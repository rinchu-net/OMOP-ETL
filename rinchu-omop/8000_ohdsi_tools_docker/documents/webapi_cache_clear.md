# OMOPデータ更新後のWebAPIキャッシュ削除手順

## 1. 目的と仕組み

OMOPデータベースのデータを更新した後も、ATLASのDashboard・Data Densityやコンセプト件数などに古い情報が表示される場合があります。本手順では、WebAPIがDBに保存したキャッシュを対象データソース単位で削除し、表示を確認します。

### 表示が更新されない主な原因

ATLASのDashboardなどは、OMOP CDMの患者テーブルを画面表示のたびに直接集計するのではなく、Achillesの集計結果を参照します。さらに、WebAPIがその結果やコンセプト件数をキャッシュしています。

これは、大量の診療データを毎回集計する負荷を避け、画面を速く表示するための仕組みです。一方、元データの更新が即座に表示へ反映されないため、OMOP CDMのデータ更新後は集計結果の更新、WebAPIキャッシュの削除、画面の再読み込みが必要になります。

| 情報の種類 | 保存先・役割 | 更新方法 |
|---|---|---|
| OMOP CDMデータ | 分析対象DBの患者・診療情報 | ETL等で更新する |
| Achilles集計結果 | 対象データソースのResultsスキーマにある集計テーブル | 更新したCDMに対して集計を再実行する |
| WebAPIのDB保存キャッシュ | WebAPI Application Databaseの `webapi.achilles_cache`・`webapi.cdm_cache` | 本手順で対象データソースの行を削除する |
| ブラウザ側の表示状態・キャッシュ | ATLASを開いているブラウザ | 再読み込みやATLASの開き直しを行う |

`achilles_cache` はDashboard等の応答を保存し、`cdm_cache` はコンセプトのレコード数・患者数等を保存します。これらはDBに保存されるため、**WebAPIコンテナを再起動するだけでは削除されません。**

> [!IMPORTANT]
> **OMOP CDMデータを更新しただけで、Achillesの集計結果が古いままの場合は、キャッシュ削除だけでは解決しません。** 先に対象データソースのAchilles集計と、利用しているコンセプト件数集計を更新してください。その後にキャッシュを削除します。

## 2. 作業の流れと前提

1. 対象DBのデータ更新と、必要な集計処理の完了を確認する。
2. キャッシュを削除するデータソースの `source_id` を確認する。
3. pgAdminで対象データソースのキャッシュ行を削除する。
4. ATLASを再読み込みし、表示を確認する。

通常、WebAPIコンテナの停止・再起動は不要です。

### 事前確認

- WebAPI Application Databaseへの参照・DELETE権限を持つ担当者が実施してください。
- キャッシュ削除前に、施設の運用方針に従ってDBをバックアップしてください。
- データ更新・集計・キャッシュ生成等のジョブが完了し、他の利用者が対象データソースを操作していない時間帯に実施してください。削除中は対象データソースのATLAS画面を開かないでください。
- 対象データソースのResultsスキーマが、更新済み集計結果の保存先と一致することを確認してください。`result` や `atlas` など、実際のスキーマ名は環境により異なります。

集計処理の実行手順は、[READMEの「4. OHDSI Tools用統計データ作成手順」](../../README.md#4-ohdsi-tools用統計データ作成手順6000_statistics)を参照してください。実行する集計処理の接続先・スキーマは、今回更新したデータソースに合わせて確認します。

> [!NOTE]
> キャッシュ削除は、コホート生成や解析結果の再計算を行う操作ではありません。既存のコホートや解析結果を更新したい場合は、それぞれの処理を別途実行してください。

## 3. 対象データソースを確認する

1. pgAdmin（http://localhost:15050/pgadmin）を開きます。
2. **Servers → omopdb_docker → Databases → OHDSI** を選択し、**Query Tool** を開きます。
3. 以下のSQLを実行します。

```sql
SELECT source_id, source_name, source_key, deleted_date
FROM webapi.source
ORDER BY source_id ASC;
```

更新したデータソースの名前・キーを確認し、`source_id` を控えます。`deleted_date` がNULLの有効な登録を対象にします。

> [!IMPORTANT]
> 以下のSQLは **`source_id = 2` を対象とする例** です。実際に確認したIDへ、以降のSQL内の値をすべて変更してください。同じOMOP DBを複数のデータソースとして登録している場合は、そのDBを参照する各source_idについて確認・削除が必要です。

## 4. キャッシュデータを削除する

手順3と同じQuery Toolで実行します。**接続先は分析対象のOMOP DBではなく、WebAPIが使用するデータベースです。** 本配布環境では、omopdbコンテナのOHDSIデータベース内にある `webapi` スキーマを操作します。

手順3で確認した `source_id` に合わせて、以下の2つのDELETE文の `2` を置き換えます。

```sql
DELETE FROM webapi.achilles_cache
WHERE source_id = 2;

DELETE FROM webapi.cdm_cache
WHERE source_id = 2;
```

> [!TIP]
> **通常は `WHERE source_id = ...` を指定し、対象データソースのキャッシュだけを削除することを推奨します。**
>
> 省略すると、各キャッシュテーブルの全レコードが削除されます。他のデータソースも、ATLASで表示する際に集計済みデータの再取得・表示用データの作成やキャッシュの再生成が必要となるため、キャッシュクリア後の初回表示に通常より時間がかかる場合があります。

2つのDELETE文がエラーなく実行されたことを確認します。片方でエラーになった場合、それ以前に成功した削除は確定済みです。原因を修正し、失敗したDELETE文を再実行してください。

## 5. ATLASの表示を確認する

1. http://localhost:18081/atlas を開きます。既に開いていた場合は `Ctrl+F5` で再読み込みし、改善しない場合はATLASのタブを閉じて開き直します。
2. **Data Sources** で、更新したデータソースを選択します。
3. **Dashboard**・**Data Density**など、更新内容に対応する表示を確認します。
4. 必要に応じて、コンセプト検索等の件数表示も確認します。

キャッシュが必要な処理では、設定やアクセス内容に応じて更新済みの集計結果からキャッシュが再生成されます。初回表示は通常より時間がかかる場合があります。画面アクセス後にキャッシュ件数が再び増えること自体は異常ではありません。

確認する値は、今回の集計結果と対応するものを選んでください。秘匿処理・集計条件・対象期間などがあるため、画面のすべての値がCDMの単純な `COUNT(*)` と一致するとは限りません。

## 6. 更新されない場合の確認点

| 状況 | 確認すること |
|---|---|
| 削除してもDashboardが古い | 今回のOMOPデータ更新後に、[READMEに記載した6000_statisticsの統計処理](../../README.md#4-ohdsi-tools用統計データ作成手順6000_statistics)が対象DB・Resultsスキーマに対して正常終了しているか、データ更新担当者に確認する |
| コンセプト件数だけが古い | 今回のOMOPデータ更新後に、[READMEに記載した6000_statisticsの統計処理](../../README.md#4-ohdsi-tools用統計データ作成手順6000_statistics)が正常終了しているか、データ更新担当者に確認する。対象 `source_id` の `cdm_cache` を削除したかも確認する |
| 削除後も古いキャッシュが再生成される | 削除前から実行中の画面要求やキャッシュ生成ジョブがなかったか。処理完了後に削除と画面の再読み込みを再実施する |
| キャッシュ件数が最初から0 | キャッシュが使われていない可能性。今回のOMOPデータ更新後にETLの6000_statisticsの処理が正常終了しているか、データ更新担当者に確認し、ブラウザも再読み込みする |
| 別のDBの内容が表示される | ATLASで選択したデータソース、`webapi.source` の接続先、`source_daimon` のスキーマ設定 |
| キャッシュが再生成されない | キャッシュ設定・アクセス内容による。0件のままでも表示が正常なら、再生成自体を目的に設定変更しない |
| 画面の再読み込み後にエラーになる | WebAPI・DBの稼働状態、接続権限、必要な集計テーブルの存在 |
