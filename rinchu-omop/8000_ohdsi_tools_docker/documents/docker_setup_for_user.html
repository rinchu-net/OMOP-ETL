利用者向けドキュメント（受領〜取り込み〜起動・動作確認）

はじめに

概要

本ドキュメントは、提供されたOHDSIツールセット（Docker版）を受領してから、ローカル環境で起動し、動作確認を行うまでの手順をまとめたものです。

対象読者

  • OHDSIツールを使用する解析担当者
  • 環境構築を行うシステム利用者

何ができるようになるか

本手順を実施することで、お手元のPC（Windows/Mac/Linux）上でOHDSIツール群（Atlas, WebAPI等）をDockerコンテナとして稼働させ、ブラウザから利用可能な状態にすることができます。

1. 前提条件

システム要件

  • メモリ: 16GB以上
  • ディスク空き容量: 20GB以上
  • OS: Windows 10/11, Windows Server 2022/2025, macOS, Linux

必要なソフトウェアのインストール

以下のいずれかのコンテナランタイムがインストールされ、起動している必要があります。

  • Docker Desktop
  • Rancher Desktop（Docker Desktopが有償ライセンス条件で利用出来ない場合の代替。dockerd モードで利用します）

  1. Docker環境のインストール: 前提となるDocker環境を準備します。
  2. 受領ファイルの配置とロード: 配布された資材を展開し、Dockerイメージをロードします。
  3. 設定ファイルの作成: 環境に合わせて .env ファイルを作成・編集します。
  4. アプリケーションの起動: controller_start.bat を実行してコンテナを起動します。
  5. ポータルページを開く: ブラウザでポータルページにアクセスしてブックマークします。
  6. 動作確認: 各サービスが正常に動作しているか確認します。

3. クイックスタート

3.1 Docker環境のインストール

1. Dockerのインストール

以下のいずれかをインストールしてください:

  • Docker Desktop: https://www.docker.com/products/docker-desktop
  • Rancher Desktop: https://rancherdesktop.io/ （Docker Desktopの代替、dockerdモードで使用）
    • インストール時の設定:
      • Container Runtime: dockerd (moby) を選択
      • Kubernetes を無効化（Enable Kubernetesのチェックを外す）

2. Dockerの起動

  • インストール後、Docker Desktop または Rancher Desktop を起動します
  • タスクバー（Windows）またはメニューバー（Mac）にDockerのアイコンが表示され、「Running」状態になるまで待ちます

3. 起動確認

  1. ターミナルを開く:
    • Windows: スタートメニューから「cmd」または「PowerShell」を検索して起動
    • Mac: Spotlight検索（⌘+Space）で「ターミナル」を起動
    • Linux: 端末（Terminal）を起動

[!TIP]
Windows環境（cmd.exe）での推奨設定
ターミナルを開いた直後、以下のコマンドを実行してコードページをUTF-8に変更することを推奨します：

chcp 65001

これにより、日本語などの多バイト文字が正しく表示されます。PowerShellの場合はこの設定は不要です。

  1. Dockerが動作しているか確認:

    docker ps

  2. 期待される結果:

    CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES

    上記のような表形式の出力が表示されればOKです（まだコンテナを起動していないため、ヘッダー行のみ表示されます）。

  3. エラーが出た場合:

    • 「docker: command not found」または「'docker' は、内部コマンドまたは外部コマンド...」と表示される場合:
      • Docker Desktop/Rancher Desktopが正しくインストールされているか確認
      • インストール後、ターミナルを再起動
    • 「Cannot connect to the Docker daemon」と表示される場合:
      • Docker Desktop/Rancher Desktopが起動しているか確認
      • アプリケーションの再起動を試してください

3.2 受領ファイルの配置とロード

  1. 配布されたzipファイル等を解凍し、作業用フォルダに配置します。
    以下の例では C:\ohdsi_tools_docker を作業用フォルダとしていますが、任意のパスに変更できます。
# フォルダ構成例（<作業用フォルダ> は任意のパスに置き換えてください）
<作業用フォルダ>/
  ├── images/
  │   ├── ohdsi-atlas.tar
  │   ├── ohdsi-webapi.tar
  │   ├── postgres.tar
  │   └── load_images.bat
  ├── postgres_data/
  ├── docker-compose.yml
  ├── .env.example
  ├── .env (このファイルは.env.exampleから作成します)
  ├── controller_start.bat
  ├── controller_stop.bat
  ├── controller_restart.bat
  ├── portal/
  │   └── portal.html
  └── README.md
  1. ターミナルで images フォルダに移動し、Dockerイメージをロードします。
# Windows (cmd.exe) の場合
chcp 65001
cd <作業用フォルダ>\images
load_images.bat

# PowerShell の場合
cd <作業用フォルダ>\images
.\load_images.bat

# Mac/Linux の場合
cd <作業用フォルダ>/images
./load_images.sh

例: Windows (cmd.exe) の場合は chcp 65001 実行後、cd C:\ohdsi_tools_docker\images とした後、load_images.bat を実行

3.3 設定ファイルの作成

.env.example をコピーして .env という名前のファイルを作成します。
必要に応じて、.env 内のパスワードやポート設定を変更します。

3.4 アプリケーションの起動

ターミナルで作業用フォルダに移動し、起動スクリプトを実行します。

cd <作業用フォルダ>
controller_start.bat

例: cd C:\ohdsi_tools_docker

初回の起動にはコンテナの初期化が含まれるため、数分かかる場合があります。

3.5 ポータルページの開き方

  1. すべてのコンテナが起動完了するまで待機します（ターミナルの出力を確認）。

  2. 以下のいずれかの方法でポータルページを開きます。

    方法1: エクスプローラーから開く（推奨）

    • エクスプローラーで <作業用フォルダ>\portal\portal.html を開いてダブルクリック
    • 例: C:\ohdsi_tools_docker\portal\portal.html

    方法2: ブラウザのアドレスバーに直接入力

    file:///C:/ohdsi_tools_docker/portal/portal.html

    ※スラッシュは / を使用し、作業用フォルダのパスに合わせて変更してください

  3. ポータルページが表示されたら、ブラウザのブックマーク機能でこのページをブックマークしてください。

    • ブラウザのアドレスバーの右側のアイコンをクリック、または
    • キーボードの Ctrl+D で追加できます

ポータルページの機能

ポータルページは、OHDSIツール群の一元的なアクセスポイントとなり、以下の機能を提供します。

機能 説明
稼働状態の確認 各コンテナ・サービスの稼働状況をリアルタイムで表示します。アイコンやステータス表示で一目で稼働状況を確認できます
各ツールへのリンク pgAdmin、WebAPI、Atlas、RStudio など各ツールへの直接リンクを提供し、ワンクリックでアクセスできます
ログイン情報の表示 各サービスのデフォルトユーザー名やパスワードが表示されており、すぐに利用可能です
トラブルシューティング よくある問題と解決方法へのリンクが含まれています
ドキュメントへのアクセス README やその他のドキュメントへのリンクから、詳細な情報にアクセスできます

  • URL: http://localhost:18787

5. Tips & Tricks

5.1 Docker DesktopとRancher Desktopでのホスト名の違い

ホストOS側のサービス（ローカルで動いているDBなど）にコンテナから接続する場合、ホスト名は以下のように指定します。

  • Docker Desktop: host.docker.internal
  • Rancher Desktop: host.rancher-desktop.internal (またはIPアドレス)

※環境やバージョンにより挙動が異なる場合があるため、接続できない場合はIPアドレス指定を試してください。

5.2 外部データベースへ接続先を変更

WebAPIが参照するCDMデータベースを外部のPostgreSQL等に変更する場合は、以下の手順で設定を変更します。

  1. 設定ファイルの選択: セクション 5.4 を参照し、application.properties.localdb をベースに設定を行います
  2. 接続情報の編集: webapi_setting/application.properties で外部DBの接続情報（ホスト名、ポート、DB名、ユーザー、パスワード）を設定します
  3. ネットワーク設定: 外部ネットワーク上のデータベースに接続する場合、docker-compose.yml でネットワーク設定の確認が必要です
    services:
  webapi:
    network_mode: bridge  # または host
  4. ファイアウォール: データベースサーバー側でコンテナからの接続を許可する必要があります
  5. 再起動: 設定変更後は controller_restart.bat でコンテナを再起動してください

5.3 各バッチファイルの説明

よく使うバッチファイルの説明は以下の通りです。

  • controller_start.bat: 全コンテナを起動します。
  • controller_stop.bat: 全コンテナを停止します。
  • controller_restart.bat: 全コンテナを再起動します。
  • load_images.bat: images フォルダ内のDockerイメージをロードします。

5.4 WebAPI の データベース接続先設定について

WebAPI コンテナの動作を制御する設定ファイルは webapi_setting/application.properties です。このファイルを編集することで、データベース接続やポート設定をカスタマイズできます。

設定ファイルのバリエーション

プロジェクトには、異なるデータベース接続先に対応した複数の設定ファイルテンプレートが用意されています。

ファイル名 データベースホスト 用途
application.properties omopdb デフォルト設定（コンテナ内PostgreSQL）
application.properties.containerdb omopdb docker-composeで起動しているPostgreSQLコンテナに接続（同一Dockerスタック内）
application.properties.localdb host.docker.internal ホストOS上で直接動作しているPostgreSQLに接続（Dockerエンジンの外、同一PC上）

各テンプレートの詳細:

  • containerdb: docker-compose.yml で定義されている omopdb コンテナ（PostgreSQL）に接続します。WebAPIコンテナと同じDockerネットワーク内で通信するため、コンテナ名で直接アクセスできます。

  • localdb: ホストOS（同一PC）上でDockerとは独立して動作しているPostgreSQLに接続します。host.docker.internal を使用してホストマシンにアクセスします。

主な違い:

# containerdb の場合（同一Dockerスタック内のコンテナに接続）
datasource.url=jdbc:postgresql://omopdb:5432/OHDSI

# localdb の場合（ホストOS上のPostgreSQLに接続）
datasource.url=jdbc:postgresql://host.docker.internal:5432/OHDSI2

主要な設定項目

データベース接続設定

Primary DataSource（メインデータソース）

項目 説明 デフォルト例
datasource.driverClassName JDBCドライバクラス org.postgresql.Driver
datasource.url WebAPI用データベースの接続URL jdbc:postgresql://omopdb:5432/OHDSI
datasource.username WebAPI用データベースのユーザー名 ohdsi_app_user
datasource.password WebAPI用データベースのパスワード app1
datasource.dialect データベース種類 postgresql
datasource.ohdsi.schema WebAPIのスキーマ名 webapi

Flyway DataSource（データベースマイグレーション用）

項目 説明 デフォルト例
flyway.enabled Flywayによるマイグレーションの有効化 true
flyway.datasource.driverClassName JDBCドライバクラス org.postgresql.Driver
flyway.datasource.url データベースの接続URL jdbc:postgresql://omopdb:5432/OHDSI
flyway.datasource.username 管理者ユーザー名（DDL権限必要） ohdsi_admin_user
flyway.datasource.password 管理者パスワード admin1
flyway.schemas 管理対象スキーマ（大文字小文字区別） webapi
flyway.locations マイグレーションスクリプトの場所 classpath:db/migration/postgresql

Security DataSource（セキュリティ用）

項目 説明 デフォルト例
security.db.datasource.url セキュリティ情報用データベースURL jdbc:postgresql://omopdb:5432/OHDSI
security.db.datasource.username データベースユーザー名 ohdsi_app_user
security.db.datasource.password データベースパスワード app1
security.db.datasource.schema セキュリティ用スキーマ名 atlas_security

その他の重要設定

項目 説明 デフォルト例
server.port WebAPI が使用するポート 8080
server.context-path コンテキストパス /WebAPI
source.name CDMデータソース名 CDM_NAME
cdm.version CDMバージョン 5

設定ファイルの編集方法

  1. ファイルの位置:

    <作業用フォルダ>\webapi_setting\application.properties

    例: C:\ohdsi_tools_docker\webapi_setting\application.properties

  2. 接続先の切り替え手順:

    テンプレートをコピーして使用します:

    cd <作業用フォルダ>\webapi_setting

# 外部DBに接続する場合
copy application.properties.localdb application.properties

# コンテナ内DBに戻す場合
copy application.properties.containerdb application.properties

    例: cd C:\ohdsi_tools_docker\webapi_setting

  3. 設定の編集と反映:

    • テキストエディタで application.properties を開き、必要な項目を編集
    • ファイルを保存後、コンテナを再起動:
    cd <作業用フォルダ>
controller_restart.bat

    例: cd C:\ohdsi_tools_docker

注意事項

  • ファイルは UTF-8 エンコーディングで保存してください
  • パスワードに特殊文字が含まれる場合はエスケープが必要な場合があります
  • Primary DataSource は通常のアプリケーション操作用です
  • Flyway DataSource はスキーマ変更やテーブル作成に使用されるため、DDL権限を持つユーザーが必要です
  • Security DataSource はユーザー認証情報の管理に使用されます
  • 3つのDataSourceは同じデータベースを指すことも、別々のデータベースを指すこともできます
  • スキーマ名は大文字小文字を区別します（特に flyway.schemas）
  • テンプレートファイルは編集せず、application.properties を編集してください
  • 設定変更後は必ずコンテナを再起動してください
  • コンテナ再起動後、セクション 4.2 で WebAPI が正常に起動していることを確認してください
